# TradeBot

A 24/7 cloud trading desk based on [design v0.7](docs/design-v0.7.md), the binding [v0.8 design addendum](docs/design-v0.8-addendum.md) and [implementation decisions](docs/decisions.md). See the [task ledger](docs/tasks.md) and [financial goals and profit protection amendment](docs/tb-fin-01.md).

**TB-03 and TB-04A accepted; TB-04B archive and stream passed, R1 gap bridge candidate pending genuine external receipt; TB-04C partition storage accepted. Paper-only, paused on startup. TB-02 native engine mechanism accepted; the dashboard does not start or control a connected worker, and no deployed services or real order capability exist.** The localhost API requires a developer-supplied admin token. Do not expose it publicly or enter production credentials; production HTTPS, first-administrator authentication, provider verification and deployment are still release gates.

Developer checks (not end-user installation): install `requirements.txt`, then run `python -m unittest discover -s tests -v`. For local API development only, set `TRADEBOT_ADMIN_TOKEN` to a random secret of at least 32 characters, and `TRADEBOT_DATA_DIR` to a private directory, then run `python -m tradebot`. The eventual supported VPS deployment will require no user-entered shell commands. Never commit credentials.

Developer-only native acceptance: `python scripts/qualify_engine.py` on a qualified Linux host with Docker, internet and the pinned FreqAI image. This is not the end-user installer. See [TB-02](docs/tb02.md).

Developer-only dashboard build: install the pinned npm dependencies with `npm --prefix dashboard ci --ignore-scripts --no-audit --no-fund`, then `npm --prefix dashboard run build`. Open `http://127.0.0.1:8765/` after starting the local service. Set `TRADEBOT_VAULT_KEY` to a separately managed Fernet key for **test** credential setup; if absent the write-only credential endpoint is unavailable. Browser tests: install Playwright 1.57.0 and Chromium, then `python scripts/test_dashboard_browser.py`. `--offline` runs a synthetic browser fixture, not acceptance of the HTTP integration. See [TB-03](docs/tb03.md). The end-user DigitalOcean Linux deployment will use a graphical installation path at TB-10; do not provision a VPS yet merely for these development checks.

TB-04A developer-only market intake: `python scripts/ingest_market.py --data-dir PRIVATE_DATA_DIR poll` obtains recent closed hourly observations for all three pairs; `poll --loop` permits bounded continuous REST polling in a separately started dev process. `archive PATH PAIR INTERVAL SHA256` imports a pre-verified official Kraken CSV; verify origin and terms separately. `export PAIR INTERVAL START END` uses the optional pinned `requirements-market.txt` native DuckDB dependency. The Market Research screen can query actual stored hourly activity; no data is invented. These are developer checks only, not the end-user deployment/continuous supervisor or complete history gate. See [TB-04A](docs/tb04.md).

TB-04B development: install `requirements-market.txt` (DuckDB 1.4.4 and websockets 16.0). `python scripts/ingest_market.py --data-dir PRIVATE_DATA_DIR bootstrap` selects official hourly CSVs by bounded HTTPS ranges (member CRC/CSV hashes, not publisher full SHA). `bootstrap --parts-dir PRIVATE_ARCHIVE_DIR` verifies pre-staged five parts and complete publisher digest; `--download-full` explicitly permits the multi-GB download/resume. `stream` connects to public WS v2 with closed REST repair; `stream-status` reports freshness and missing ranges; `bridge-gap PAIR START END --max-pages 64` checkpoints trade-derived recovery between two independently known hourly anchors, exclusive end. Developer-only operation; production GUI/background supervision is still a release gate. Actual external qualification pending; see TB-04B in [intake notes](docs/tb04.md).

TB-04C developer-only storage maintenance with `scripts/manage_history.py --data-dir PRIVATE_DATA_DIR`: `compact PAIR INTERVAL START END` publishes bounded historical partitions; `query-history PAIR INTERVAL START END --as-of EPOCH` uses verified Parquet plus journal tail, `storage-status` measures usage, `storage-policy QUOTA_BYTES RESERVE_BYTES` sets derived storage admission, `pin-partition ID LABEL` protects a generation (`--release` removes that pin), `prune-retired BEFORE` and `recover-orphans` are dry-run unless `--apply`. Use UTC epoch seconds and aligned candle windows. No authoritative source deletion. Native local scale test: `python scripts/qualify_market_lake.py` generates temporary synthetic data; not real historical coverage. User Market Research includes read-only storage status. Whole-store backup, raw-source quota and production maintenance scheduling remain gates; see [TB-04C](docs/tb04.md).
