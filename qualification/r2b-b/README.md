# TB-SEC-KEY-01-R2B-B — Separate Telegram pairing and secure test notification
2026-11-20. Standalone development candidate only; D2 tree a9cd0f3392a573d3c91cc2d8464c4b8de5eefb0b unchanged. No real token, Telegram request, notification, financial action or LIVE authority.

## Implemented
- Separate Desk and Recovery roles; distinct positively inspected bot IDs (same recipient permitted). Refuse bot reuse across pending or bound roles. Verify token's bot identity using getMe; match the returned identity to the token prefix, check username formatting. Inspect selected numeric chat with getChat and require exact ID and private chat. Initial scope deliberately excludes groups/channels/username targets; private chat metadata is not proof of the human recipient's identity.
- Preview includes role, bot username, chosen chat ID and a one-time expiring review for the trusted operator surface. No message on preview, invalid input, cancellation or stale confirmation. Require explicit True approval; bind review to role and current vault generation and re-inspect bot/chat before sending. Replacement/removal invalidates the old review. No raw tokens in preview; identifiers hidden from repr. These are in-memory review semantics, not durable authorization or authenticated GUI.
- Send exactly one fixed non-financial role-specific test message, no custom text, paid broadcast, arbitrary method, commands, restart, money or trading authority. Validate successful response sender, recipient, message ID and message text; report test_accepted_by_telegram (not human read/receipt) or delivery_unknown. No automatic retry of ambiguous delivery. A new test must be reviewed explicitly. HTTP 429, refusal and timeout safely fail unverified/unknown; richer retry-after handling and operator status distinctions are deferred.
- Fixed TLS-validated HTTPS host api.telegram.org, POST, allowlist getMe/getChat/sendMessage, bounded response 64 KiB, socket timeout, no redirect or environment proxy. Telegram requires token in request path; never emit the credential-bearing URI, raw provider response or exception. No incoming updates, webhook or control command path. Protect content is requested for the test but is not a confidentiality guarantee.
- Provider contract: https://core.telegram.org/bots/api (getMe, getChat, sendMessage); https://core.telegram.org/bots/tutorial. Recipient must have an existing authorized private interaction with the bot; no chat discovery implementation in this candidate.
