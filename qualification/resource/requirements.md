## TB-10-RESOURCE-03 — Deterministic resource controller
Independent host-supervised scheduler, not model-directed. Start with measured limits, adapt only within reviewed configuration. Linux cgroup v2/systemd service custody, per-job memory/CPU/IO budgets and ownership, protected critical service headroom, one heavy background job at a time on low-memory hosts, explicit bounded jobs/queue and retry/backoff. Bound DuckDB query memory and threads, data batch sizes, native model threads/training working set and cleanup staging; no automatic loss of evidence or models. Admission checks available memory, pressure, reserved disk/inodes, freshness, critical-service liveness and durable recovery state; stale/unknown readings refuse discretionary jobs. Use configured hysteresis to avoid thrashing and checkpoint/cancel only work supporting safe resumption, or restart an unfinished fit without destroying the last verified model. Avoid supervisor killing critical ledger/vault/exit/reconciliation services as a normal resource policy; platform OOM must produce durable fault/entry pause and explicit reconciliation. A resource decision never bypasses independent financial gates or grants credential access, starts trading, modifies allocation/strategy, approves orders or withdraws funds.
Priority: (1) credential custody, ledger, risk gate, reconciliation and authorized protective exits, (2) freshness/collection and essential monitoring, (3) bounded inference and user-facing status, (4) training/backfills/compaction/backups when safe. Defer lower priority work as necessary; ensure timely required backups with explicit staleness warnings and entry pause if policy requires. If model/source freshness or gate availability fails, pause new entries, report exact reason and preserve independently qualified exit/reconciliation path; never guarantee exits if host/network unavailable. Separate user-facing settings/health from sensitive engineering diagnostics. No raw secrets/PII in receipts.
