## Local-first development policy — 2026-11-18

Use the local workspace for implementation, rapid regression tests, API/browser checks where available, and consolidated pre-publication verification. Publish grouped verified changes to the existing GitHub repository; do not use remote CI as the individual edit/test loop. Use native remote acceptance only for required platform, container or external connectivity evidence that cannot be reproduced locally, and at consolidated task-group gates. Existing automated workflows remain intact as safeguards, not a reason to stop unrelated development. ## TB-03 dashboard decisions — 2026-11-18

Use a same-origin responsive React dashboard served by the loopback-only FastAPI development service, not a second execution layer. The development admin token lives in transient browser memory; no cookie, local/session storage or secret readback endpoint. Local authentication is not production administrator pairing, TLS or session management. The GUI accepts test credentials only until secure deployment is qualified; write-only encrypted setup requires an externally supplied vault key. Kraken key/secret replacement is atomic, and the UI explicitly marks all connections unverified. Provider permission verification, chat pairing/test messages, recovery, real calendar events, history/preparation tasks, research and execution supervision remain unimplemented until their existing task groups.

The authenticated user may explicitly set a persistent simulated capital cap within the existing hard numeric range, never below allocated paper capital. The prior startup cap remains the initial value, until a graphical change. No real balance, order, fee or spend is implied by this cap or per-instance research budget. Legacy instances migrate to a paper-only Grok planning profile without inventing a model ID; the wizard collects a requested model and history, not qualified readiness. No start/resume or live mode endpoint is added.

Local Python and offline Chromium checks are first-line. The workspace has Chromium but direct local navigation was blocked by its managed policy, and npm registry DNS failed; no attempt to bypass these restrictions. The locally available React 16 fixture verifies UI interactions only. Release dependency pins target React 18.3.1 and its explicit transitive versions, with local UMD assets, no CDN. Registry-backed installation, dependency integrity lock generation, packaged React and actual browser-to-API verification still required. One consolidated remote browser acceptance workflow is provided solely because the local constraints prevent these gates.

Numerical-only paper strategies operate without AI under their own gates; research-dependent strategies fail closed for missing required research. Finish TB-01–TB-12 before separately authorized Cognitum HDC/KAN research TB-R01. No new paid services, automatic promotions, or current Cognitum integration.

## TB-04A staged development decision

Implement durable SQLite ingress/checkpoint and revision metadata first, with exact decimal source values retained until the native DuckDB/Parquet export, partition/query and recovery paths are fully qualified. This is staging, not a change to the final SQLite + Parquet + DuckDB storage architecture. A private developer-only importer accepts checksum-verified, operator-staged Kraken CSVs (origin/terms still require qualification); no claim that a checksum alone proves exchange origin. Public REST collector supports recent closed hourly candle observations without LLMs or keys. All sources have publication/availability timestamps; incomplete or conflicting observations are withheld, fixture evidence is excluded from public views. The dashboard presents observed coverage and 168 bins only from available history. Later TB-04 work must acquire actual archives, qualify WebSocket/reconnect/backfill and full Parquet query/retention, macro and other evidence, richer liquidity/cost measurements, complete preparation control and measured historical readiness. TB-R01 later consumes read-only database and paper streams and acts only on isolated simulated venues, never a live account.
