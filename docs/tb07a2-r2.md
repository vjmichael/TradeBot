# TB-07A2-R2 — integrated leased paper owner and authenticated recovery

The installed desk remains PAPER/PAUSED. No activation, no live orders, no user/model order API or automatic service provisioning. This candidate changes the explicit paper worker service from recovery-only to a single owner for already-authorized intents and protective exits. It holds the workspace lease through native initialization, admission claim, protection, reconciliation and cleanup. No independent strategy entries; unresolved state always takes priority over a fresh entry. The Gate checks the current independently authenticated financial observation at both admission and claim. The worker does not broaden any risk or capital limits.

A private 32-byte per-workspace receipt key is required (there is no default key or automatic creation). Raw terminal native order receipts capture exact USD fees, quantity, price and gross before ORM callbacks consume them. A separate durable receipt SQLite database uses authenticated immutable typed records; conflict and mismatch quarantine, not fee inference. Open cumulative partials remain held; terminal filled portions are reconciled by the inherited R1 worker. A prior terminal fee can be re-read after losing in-memory native exchange data. Missing, tampered or conflicting evidence prevents accounting/release; protective sells remain independent. Signatures authenticate the dedicated worker, NOT a physical exchange, and do not defend against a compromised worker UID. The flat native wallet observation binds the exact instance, workspace inode identity, financial head, boot generation, execution anchor, timestamp, native quote and base quantity. The private atomic spool requires all enrolled instances, with no outstanding execution; refuses stale/replayed/tampered packets. It does not refresh the account underneath an authorized intent. The authenticated projection revalidates the complete evidence and balances during admission and claim. Protected classification remains internal bookkeeping; native Wallets does not provide separate protected subaccounts. No direct API for unsigned balances is exposed. Existing fixture-only ledger methods remain internal and are not trusted by the installed Gate.
