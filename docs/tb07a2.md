# TB-07A2 — controlled native paper bridge (bounded candidate)

The bridge is deliberately paper-only and internal. The default stopped NoEntry configuration, desk pause checks, lack of live authorization and operator financial approval remain unchanged. A model can propose; it never owns the native bot or database. No automatic worker start, API listener, credential use, withdrawal, strategy change or release of a claim is provided.

## Entry protocol

A trusted exclusive owner constructs the optional GatePaper configuration with a separate native SQLite database. NativeDriver checks native bot/configuration and database identity, PAPER/spot USD, one pair, no keys, no FreqAI/Telegram/API, stopped state and absence of open native positions/orders. Gate claim commits before native work; bind the attempt to the isolated database identity and intent tag. A final guard checks current claim, pause, clock and expiry under the desk transaction at native exchange.create_order. Freqtrade's strategy callback is not enough because its upstream safe wrapper can default to allow on exception. GatePaper emits zero autonomous entry signals, disables position adjustment, and only arms the exact tag/side/rate for the guarded entry. No new trade can be sent again from the same intent. The pinned simulator can convert a crossing limit into a market order; conservatively reserve 5% price headroom, bound fee and precision, and quarantine conversion or unexpected price/cost. Any crash/refusal/missing persistence remains an unknown outcome. No assumption that an empty native database equals verified absence of a fill.

## Terminal receipt and accounting

Open a consistent read-only native SQLite snapshot and match an exact intent tag. Accept only a closed one-buy/one-sell paper round trip with no other open positions or orders; confirm native order IDs, pair, long spot mode, quantity, USD fees and native realized P/L. A single terminal partial entry may be supported if entirely disposed; multiple orders, open partials and non-USD fees refuse. The actual Freqtrade Wallets object recomputes paper quote/base balances independently of Maj Vaj's ledger from the native engine's own persisted data; this is not physical exchange evidence. Compare the native observed wallet to atomic buy/sell/settlement ledger replay. Unknown or differing evidence rolls back without unlocking the hold. If confirmed, record exact receipt once and protect settled positive gain. The claim stays FILLED_HELD even after successful import; it cannot free risk or bankroll by itself.

## Qualification boundary

Local 47/47 tests use actual SQLite desk/accounting files and explicit native schema/claim/driver fixtures, not a native Freqtrade session. The existing pinned native engine workflow is extended with a network-disabled probe exercising native FreqtradeBot.execute_entry, Exchange dry-run simulator, Trade/Order persistence and Wallets using a synthetic book, fee and ancillary callbacks, then a controlled terminal sell. Actual native probe is not locally executed because Freqtrade and Docker are unavailable. The protected installed worker, OS process and DB custody, bounded public-market input, true autonomous protective exits, open/partial fill reconciliation and safe accounted-hold release still require qualification under TB-07A2-R1. No actual real-market order or trading readiness asserted.
