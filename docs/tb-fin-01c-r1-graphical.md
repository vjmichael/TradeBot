Existing parent requirements: authenticated local approval broker (TB-FIN-01C-R1), graphical multi-portfolio controls (TB-08), FIN-01D/E acceptance. This is a continuation of the existing guided workflow in docs/tb-fin-01.md, not new scope.

## Implemented candidate

The independent native Tk approval application reserve_graphical.py reads only the current saved draft for the selected PAPER portfolio from the existing desk database. It displays exact policy terms, current booked balances and independent financial/risk evidence. Activation or replacement requires a one-time exact confirmation, separate encrypted-store passphrase authentication, five-minute wall/monotonic expiry and exact draft ID/digest, previous active policy, journal head and boot. Re-read all state under the same serialized transaction, verify current authenticated account evidence and hard limits. No authentication key or password enters the browser dashboard, research/strategy APIs or scheduler. No HTTP activation route, no external network, no market order.

One signed reserve_adopt event atomically saves and activates the reviewed immutable version, or leaves the previous active version intact on failure. No immediate release or catch-up; existing eligible surplus is excluded as before. The ordinary dashboard continues to save inactive drafts only. Current authorization is confirmed in the independent window by validating the signed activation receipt and effective time, not a client-side toggle. Revocation binds the exact current version, requires local human approval, and commits without waiting for a fresh wallet observation or a healthy inactive draft. It is serialized against scheduled ticks, can stop future releases immediately upon committed revocation, and never reverses earlier releases or interferes with protective exits. A corrupt financial journal remains a hard blocker: no false OFF claim. Record state or a failed refresh is not verified ON/OFF.

Keyless scheduler now binds each proposed tick to exact active version and UTC cycle, rejecting a stale tick against a replacement. Production worker entry point also requires authenticated whole-desk receipt evidence before actual release; no signed approval key is provided to that worker. Direct internal fixture calls retain injected verifier/clock capabilities. Prior approval format and historical events preserved. Activation checks current desk pause, evidence freshness, settlement, financial conflicts, risk and hard caps. New code does not enable desk RUN, any real funds, automatic reinvestment or an actual host timer.
