# TB-02 — Native paper engine qualification

Candidate (not closed). Official Freqtrade 2026.10 FreqAI image pinned to the published Linux/amd64 child digest on Docker Hub in `engine.py`; no mutable stable/latest tags. Upstream sources: https://github.com/freqtrade/freqtrade/pkgs/container/freqtrade/versions and https://www.freqtrade.io/en/stable/freqai/ . Kraken public OHLC endpoint: https://docs.kraken.com/api/docs/rest-api/get-ohlc-data/ . No exchange secrets are sent by the public adapter or passed to the engine. No Docker socket, secret vault or broad host directory is mounted into the engine container.

- Authenticated recent market candles for BTC/USD, ETH/USD, SOL/USD via fixed GET-only REST endpoint, no redirects, finite numeric validation, strict pair/timeframe whitelist, chronological check, gap count, freshness, and removal of Kraken's still-forming last candle. Kraken's maximum recent 720 rows is not historical readiness. No private account requests.
- Fixed paper config from validated `InstanceSpec`, separate wallet, one trading pair, spot only, empty key and secret, stopped state, no force entry, no direct Telegram or REST execution server. NoEntry strategy has no signals. App remains paused and reports engine disconnected until lifecycle integration is qualified. The harness uses an isolated scratch directory, fixed digest, bounded CPU and memory and cleanup.
- Native CI job pulls the image, tests genuine Kraken public data for all pairs and uses Freqtrade's own market list. It starts the real Freqtrade worker with a no-entry dry-run strategy, checks the stopped state and zero trades in the engine database, and then destroys the container. In a separate scratch workspace it uses deterministic **synthetic** candles to exercise genuine LightGBM training through FreqAI, requiring saved model artifacts and completed fee-bearing simulated trades from exported backtest results. Synthetic data and intentional test signals prove the mechanism, not performance. Training horizon and fee are smoke-test parameters, not production defaults or an estimate of the user's actual fee tier.
- Current execution environment has neither Docker nor DNS access. Python foundation plus adapter and image pin tests pass (14 total); native job must pass on exact candidate before TB-02 can be closed. Live market dry-run fills, runtime supervision and durable reconciliation, real historical backfill (including Kraken trade-to-OHLCV), real model/evidence features, leakage-safe walk-forward experiments and fee/slippage/venue qualification remain required. No automatic live promotion.
