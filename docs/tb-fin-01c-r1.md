# TB-FIN-01C-R1 — local operator review and keyless scheduler

## Implementation boundary

The candidate introduces a local, developer-only operator approval broker and separate keyless Linux worker. The broker creates a random signing key once, encrypts it using AES-256-GCM with a salted scrypt-derived key from an operator passphrase, and stores only ciphertext in a private owner-only credential file. Exclusive provisioning never replaces an existing key. A five-minute one-use review binds the exact named paper instance, saved policy version, requested action, journal head and boot generation, and displays current status and activation preview. The interactive terminal requires an explicit matching challenge and passphrase. Reconciliation or restart invalidates a pending review; the exact-version restrictive revocation may survive intervening observations. The existing ReserveManager commits approval and reserve event together, and stores the authenticated grant in the hash-chained journal. Reused activation versions cannot reset lifetime budgets. Keyless managers only evaluate ticks. Status reports expired authorization as OFF without silently undoing previous releases.

The worker never opens the signing credential store, starts or creates the desk, unpauses the desk, installs a service, or issues orders. It opens an existing private schema-v4 database read/write, serializes against desk transactions, and evaluates each active instance using a stable per-version UTC cycle receipt. A separate exclusive OS file lock prevents concurrent worker processes; SQLite protects ledger serialization on crash or restart. The explicit-install Linux systemd timer invokes a bounded oneshot service twice per minute with no persistent catch-up, network isolation, restricted filesystem and control-group termination. The existing risk and settlement constraints remain mandatory; a cycle skipped for stale evidence or locks is not retried as a release. An earlier portfolio's financial event invalidates the whole-desk reconciliation until refreshed; the operational multi-instance scheduler will require fresh independent observations between evaluations.

## Developer qualification only

The local approval process is not the production dashboard or a remote authentication endpoint. No credential is provisioned by default. Use a private test desk and a separate owner-only credentials directory, private desk database, and interactive terminal. The module exposes developer commands init, review, status and tick; review uses an exact JSON payload, not shell-entered secrets. The passphrase is entered through a terminal prompt. No credentials are supplied to the timer. Do not expose this service publicly, enable it against a live account or interpret the configuration as permission to trade. The production deployment must still establish OS/broker custody separating agents from financial database and signing material, qualified operator authentication and recovery, scheduler service lifecycle and independently sourced execution reconciliation. Same-UID database writers or a compromised host are not a demonstrated security boundary.

Local qualification: 41/41 focused tests passed, comprising 20 prior ledger/reconciliation tests, 13 reserve foundation tests and 8 runtime tests. Real SQLite files, encrypted credential provisioning and rejection, stale/expired/replayed review, version-reuse prevention, revocation, effective expiry, keyless scheduler idempotency, and actual separate worker process plus exclusive-lock contention were exercised. UTC calendar expression was validated with systemd-analyze calendar. Actual systemd service installation and supervision were not exercised; no production approval or real funds were used. Full repository and native unchanged-SHA acceptance remain separate. User-facing financial FAQ is docs/README-finances.md.
